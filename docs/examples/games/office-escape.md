# Office Escape

> Демонстрирует: процедурная генерация (BSP комнаты-коридоры), камера на карте больше экрана, `update(dt)`, `draw()`, `engine.onKey`, `cpp_draw_rect`, `cpp_draw_text_*`, `cpp_rand`, машина состояний, сцена без объектов

## Механика

Сотрудник сбегает из офисной башни в **5 этажей**. Старт — на верхнем этаже; каждый этаж — процедурно сгенерированная планировка из кабинетов и коридоров. Нужно дойти до **лифта** и спуститься этажом ниже; лифт на **первом этаже** = **YOU ESCAPED!**.

Каждый шаг повышает **стресс**. Стресс **100% = выгорание = поражение**. На полу разбросан **кофе** — он снижает стресс. При спуске на следующий этаж стресс **обнуляется** — каждый этаж это отдельная самодостаточная задача.

### Управление

- **WASD** или стрелки — шаг по сетке.
- **R** — рестарт.
- **Enter** — старт / новый забег с экранов TITLE / WIN / BURNOUT.

## Файлы

- `samples/scenes/office_escape.json` — сцена (только список скриптов, без объектов).
- `samples/scripts/office_escape/gen.lua` — генератор карты (чистая модель).
- `samples/scripts/office_escape/logic.lua` — игровая модель (стресс, кофе, лифт).
- `samples/scripts/office_escape/game.lua` — оболочка: ввод, камера, рендер, экраны.

## Карта: BSP комнаты и коридоры

Карта — сетка **48×32** тайла (мир 2304×1536 px при TILE 48), что **больше окна** 1280×720 примерно в 1.8×2.1 раза. Планировка строится рекурсивным **BSP-разбиением**: поле делится пополам, пока регионы не станут небольшими, в каждом листе вырезается прямоугольный кабинет, а соседние кабинеты соединяются **L-образными коридорами**. Связность гарантирована самим деревом разбиения — отдельная проверка достижимости не нужна.

Старт — центр случайной комнаты; лифт — клетка пола из **дальней трети** по реальной BFS-дистанции от старта (всегда далеко, но не всегда в противоположном углу).

> Детерминизм карты обеспечивает `cpp_rand` (засеян на стороне C++): в движке `os` нет, поэтому прежний `math.randomseed(os.time())` всегда давал seed 0 и одну и ту же карту — теперь карта разная при каждом запуске.

## Гарантированная проходимость

Каждый этаж обязан проходиться. Оптимальный игрок идёт кратчайшим путём длиной `L` шагов, что стоит `L × 2` стресса. Кофе раскладывается **прямо на этом пути** так, что суммарное облегчение покрывает стоимость пути:

```lua
local sps    = OfficeLogic.STRESS_PER_STEP   -- 2
local relief = OfficeLogic.COFFEE_RELIEF      -- 25
local L      = #path - 1
local needed = math.ceil(L * sps / relief)    -- чашек на пути
local gap    = relief // sps                  -- не реже чем раз в 12 тайлов
```

Каждый этаж начинается с нулевого стресса (он обнуляется при спуске), а `needed × relief ≥ L × sps` делает **итоговое изменение стресса за этаж ≤ 0**. Чашка не реже чем раз в `gap` (= 12) тайлов держит подъём между кофе ниже `gap × sps` (= 24), так что пик далеко от 100. Эмпирически на 1000 полных 5-этажных прогонов пик стресса ≤ 48%.

## Камера на карте больше экрана

Так как мир больше окна, `game.lua` ведёт камеру за игроком: цель — отцентрировать игрока, значение **lerp-сглаживается** (`k = min(1, dt × CAM_SPEED)`) и **клампится** к границам мира, чтобы за внешней стеной не было пустоты. `draw_board()` рисует **только видимый диапазон тайлов** (`r0..r1, c0..c1`), а не все 1536.

```lua
local function camera_target()
    local tx = math.max(0, math.min(WORLD_W - VIEW_W, render_cx - VIEW_W / 2))
    local ty = math.max(0, math.min(WORLD_H - VIEW_H, render_cy - VIEW_H / 2))
    return tx, ty
end
```

HUD (FLOOR / STRESS / COFFEE) и экраны (TITLE / WIN / BURNOUT / карточка этажа) рисуются в экранных координатах поверх доски.

## Архитектура: модель и оболочка

Игра разделена на чистую модель и императивную оболочку:

- **`gen.lua` (`OfficeGen`)** — `generate(rows, cols) → grid, items, elevator, start`. Чистая функция без движка: в тестах работает на обычном `lua5.4` (через fallback `cpp_rand → math.random`).
- **`logic.lua` (`OfficeLogic`)** — правила: `try_move`, `pickup`, `add_stress`, `descend`. Тоже без движка, покрыта юнит-тестами.
- **`game.lua`** — единственная часть, завязанная на движок: `engine.onKey`, `update(dt)`, `draw()`, камера и состояния `TITLE / PLAYING / FLOOR_CARD / WIN / GAME_OVER`.

Такое разделение позволяет тестировать генерацию и баланс без движка:

```bash
cd samples
lua5.4 ../tests/scripting/office_gen_test.lua    # карта + гарантия проходимости
lua5.4 ../tests/scripting/office_logic_test.lua  # стресс / кофе / лифт
```

**Паттерны:**
- **Процедурная генерация через BSP** — комнаты в листьях дерева, коридоры между сёстрами.
- **Калибровка баланса BFS-ом** — кофе на кратчайшем пути гарантирует проход.
- **Камера с клампом и кулингом** — карта больше экрана, рисуется только видимое.
- **Чистая модель + оболочка** — генерация и правила тестируются без движка.
